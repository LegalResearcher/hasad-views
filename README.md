# Hasad Views

يسحب منشورات قناة `@hasadalyoum` ويرسل طلب مشاهدات لرابط واحد من الطابور في كل تشغيل.
التشغيل كل 25 دقيقة عبر Supabase `pg_cron`، الذي يرسل `workflow_dispatch` إلى GitHub Actions.

## الإعداد
1. أضف أسرار الحسابات الثلاثة من Settings > Secrets and variables > Actions:
   - الحساب 1: `SITE_USERNAME_1` و`SITE_PASSWORD_1`
   - الحساب 2: `SITE_USERNAME_2` و`SITE_PASSWORD_2`
   - الحساب 3: `SITE_USERNAME_3` و`SITE_PASSWORD_3`
2. في Supabase Vault أضف سر GitHub باسم `github_actions_token`، ويجب أن يملك صلاحية تشغيل Actions للمستودع.
3. تشغيل يدوي: تبويب Actions > Hasad Views > Run workflow.

## كيف يعمل
- أول تشغيل: يأخذ أحدث منشور فقط.
- بعدها: كل منشور جديد يدخل الطابور بالترتيب، ويُنفَّذ الأقدم أولاً.
- الرابط الذي يفشل 3 مرات يُتخطى.
- يختار كل تشغيل حسابًا واحدًا للمهمة كاملة بالتناوب: 1 ثم 2 ثم 3 ثم يعود إلى 1. التناوب مشترك بين التشغيل الدوري والإعادة اليدوية، ويُحفظ مؤشر الحساب التالي في `state/account_rotation.json`.
- يلزم ضبط الأسرار الستة للحسابات الثلاثة؛ عند غياب أي منها أو تلف ملف المؤشر، يتوقف السكربت بأمان. ملف المؤشر لا يحتوي على بيانات دخول.
- يتم تسجيل الدخول إلى الموقع وإرسال الطلب من خلال نموذج المتصفح، مع النقر البرمجي على زر التأكيد لتجاوز العناصر العائمة.

## تصفير الحالة
احذف الملفات داخل مجلد `state/` (ما عدا `.gitkeep`) لبدء من الصفر.

## ملاحظة
المفتاح لا يُكتب في أي ملف. المستودع عام، فملفات `state/` مرئية للجميع.
